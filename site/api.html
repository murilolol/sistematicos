Mapa de rotas — as 80, completas

Autorização não é por rota — é um middleware aplicado uma vez na entrada. "Sessão" basta um cookie válido; "Dono ou admin" também confere posse do recurso; "Admin" restringe a ADMIN_RAS; "Pública" não exige nada. Sessão (implícita)* marca rotas acadêmicas sem o middleware requireAuth explícito, mas que dependem de ssid/ssidchk resolvidos pelo fefSessionMiddleware — sem sessão, a chamada ao portal falha adiante, só sem o 401 limpo.

Chamando a API

A única rota segura para testar sem sessão é a pública. Em Python, TypeScript ou cURL, a chamada é a mesma coisa: um GET comum.

cliente.pypython
import requests

resp = requests.get(
    "https://sistematicos.site/api/fef/cursos",
    timeout=10,
)
resp.raise_for_status()

for curso in resp.json():
    print(f"{curso['title']} -> {curso['url']}")
cliente.tstypescript
interface Curso {
  title: string;
  url: string;
  icon: string;
}

async function listarCursos(): Promise<Curso[]> {
  const res = await fetch("https://sistematicos.site/api/fef/cursos");
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

Login e sessão nas duas linguagens

O login exige RA e senha reais de um aluno da UniFEF — não dá para testar sem uma conta. O que importa aqui é o formato: o cookie de sessão volta no header Set-Cookie, nunca no corpo.

login.pypython
import requests

session = requests.Session()  # guarda o cookie sistematicos_sid entre chamadas

resp = session.post(
    "https://sistematicos.site/api/login",
    json={"username": "SEU_RA", "password": "SUA_SENHA"},
    timeout=15,
)
if resp.status_code == 401:
    raise SystemExit("RA ou senha incorretos")
resp.raise_for_status()

perfil = resp.json()["user"]
print(f"Logado como {perfil['fullName']} ({perfil['course']})")

# A sessão fica no cookie jar — reuso automático nas próximas chamadas.
boletim = session.get("https://sistematicos.site/api/boletim").json()
authenticatedFetch.tstypescript
// Versão simplificada do wrapper real do AuthContext: intercepta 401,
// força uma renovação reativa da sessão FEF e só então repete a chamada.
async function authenticatedFetch(input: string, init: RequestInit = {}) {
  const res = await fetch(input, { ...init, credentials: "include" });
  if (res.status !== 401) return res;

  const renewed = await fetch("/api/session/me?reactive=1", { credentials: "include" });
  if (!renewed.ok) throw new Error("Sessão expirada — faça login novamente");

  return fetch(input, { ...init, credentials: "include" });
}

O padrão de autorização, em código

Os três middlewares reais de server/index.js — o RA vem sempre do cookie de sessão, nunca do corpo da requisição.

server/index.jstypescript
const getAuthRa = (req) => req.fefSession?.ra || null;

// Rejeita a menos que exista uma sessão válida — qualquer aluno autenticado passa.
const requireAuth = (req, res, next) => {
  const ra = getAuthRa(req);
  if (!ra) return res.status(401).json({ error: 'Autenticação necessária' });
  req.authRa = ra;
  next();
};

// Rejeita a menos que o RA da sessão esteja em ADMIN_RAS.
const requireAdmin = (req, res, next) => {
  const ra = getAuthRa(req);
  if (!ra || !ADMIN_RAS.includes(ra)) {
    return res.status(403).json({ error: 'Acesso negado' });
  }
  req.authRa = ra;
  next();
};

// Rejeita a menos que o RA da sessão seja o dono do recurso, ou admin.
const requireOwnRaOrAdmin = (extractTargetRa) => (req, res, next) => {
  const ra = getAuthRa(req);
  const targetRa = extractTargetRa(req);
  if (!ra || !targetRa || (ra !== String(targetRa) && !ADMIN_RAS.includes(ra))) {
    return res.status(403).json({ error: 'Acesso negado' });
  }
  req.authRa = ra;
  next();
};

// Uso: extractTargetRa lê o dono real do recurso, não um campo do cliente.
app.delete(
  '/api/tasks/:id',
  requireOwnRaOrAdmin((req) => tasks.find((t) => t.id === req.params.id)?.ra),
  deleteTaskHandler
);
